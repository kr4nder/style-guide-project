# Работа с Markdown

Раздел описывает, как писать исходный текст, чтобы линтер его принимал, а diff в Pull Request читался легко.
Большую часть правил проверяет `markdownlint`.

## М1. Заголовки и пустые строки

- Используйте заголовки в формате ATX: `# Заголовок`.
- Отделяйте заголовки, списки, таблицы и блоки кода пустыми строками.

## М2. Маркированные списки

- В качестве маркера используйте дефис `-`.
- Вложенные списки сдвигайте на четыре пробела, так требует MkDocs.

## М3. Нумерованные списки

Нумеруйте пункты последовательно: `1.`, `2.`, `3.`.

## М4. Блоки кода

Блок кода всегда указывает язык: `bash`, `json`, `yaml`, `markdown`, `text`.

## М5. Имена файлов

- Имена файлов — строчными латинскими буквами, слова через дефис: `create-project.md`.
- Один файл — одна тема.

## М6. Перенос строк

Начинайте каждое предложение с новой строки в исходном тексте.
В готовом документе строки объединяются, а в diff видно, какое именно предложение изменилось.

## М7. HTML

Не используйте HTML-теги. Для клавиш, примечаний и таблиц есть синтаксис Markdown.

## М8. Конец файла

Файл заканчивается одним переводом строки. Пробелов в конце строк нет.

## Проверка

Запустите линтер перед созданием Pull Request:

```bash
npx markdownlint-cli2 "**/*.md"
```

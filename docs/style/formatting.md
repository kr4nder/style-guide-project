# Оформление текста

Раздел описывает, как оформлять заголовки, списки, таблицы, код, изображения и ссылки.

## Ф1. Заголовки

- На странице один заголовок первого уровня.
- Не пропускайте уровни: после `##` идёт `###`, а не `####`.
- Не ставьте точку в конце заголовка.
- Не используйте больше трёх уровней вложенности.

## Ф2. Названия документов

| Вид документа | Правило | Пример |
| --- | --- | --- |
| Инструкция | Отглагольное существительное | Создание проекта |
| Справочник | Название объекта или метода | Метод «Создать задачу» |
| Концепция | Название понятия | Права доступа |

## Ф3. Элементы интерфейса

- Названия кнопок, полей и пунктов меню выделяйте **полужирным** и пишите точно как в интерфейсе.
- Путь по меню записывайте через стрелку: **Настройки → Профиль → Уведомления**.
- Не заменяйте название элемента описанием: пишите «Нажмите **Создать**», а не «Нажмите зелёную кнопку».

## Ф4. Код, команды и имена файлов

- Фрагменты в строке оформляйте обратными апострофами: `docs/index.md`, `project_id`.
- Блоки кода оформляйте тройными апострофами с указанием языка.
- Команды пишите без приглашения командной строки (`$`), чтобы их можно было скопировать.

## Ф5. Клавиши

Клавиши записывайте через `++`: ++ctrl+s++, ++enter++.

## Ф6. Подставляемые значения

Значения, которые читатель должен заменить своими, пишите в угловых скобках в нижнем регистре через подчёркивание: `<project_id>`.
Под блоком кода расшифруйте каждое значение.

```bash
curl -H "Authorization: Bearer <access_token>" https://api.taskflow.example/v1/projects/<project_id>
```

Где:

- `<access_token>` — токен доступа;
- `<project_id>` — идентификатор проекта.

## Ф7. Списки

- Нумерованный список используйте для последовательности действий, маркированный — для набора равноправных элементов.
- Перед списком ставьте вводную фразу с двоеточием.
- Элементы списка начинайте с заглавной буквы и делайте однородными по грамматике.
- Точку в конце ставьте только у элементов, которые являются полными предложениями.
- Не делайте список из одного элемента.

## Ф8. Таблицы

- У каждой таблицы есть строка заголовков.
- Не используйте таблицы для вёрстки.
- Пишите в ячейках коротко: до двух предложений.
- Перед таблицей ставьте вводное предложение.

## Ф9. Примечания и предупреждения

Используйте блоки допустимых типов:

| Тип | Когда использовать |
| --- | --- |
| `note` | Дополнительная информация |
| `tip` | Совет, как сделать удобнее |
| `warning` | Действие может привести к потере данных или ошибке |

- Предупреждение ставьте перед шагом, к которому оно относится.
- Не используйте больше одного блока на экран.

Пример:

```markdown
!!! warning "Внимание"
    Удаление проекта нельзя отменить.
```

## Ф10. Изображения

- Альтернативный текст обязателен: он описывает, что показано на изображении.
- Формат — PNG, ширина — не более 800 пикселей.
- Подпись пишите в формате «Рисунок N — Описание».
- Скриншот не заменяет текст: все действия описывайте словами.

## Ф11. Ссылки

- На страницы этого руководства ссылайтесь относительными путями.
- Текст ссылки должен описывать, куда она ведёт. Не пишите «здесь» и «по ссылке».
- Внешние ссылки проверяйте перед публикацией.

# Руководство по стилю документации TaskFlow

Руководство по стилю — набор правил, по которым команда пишет и оформляет документацию сервиса TaskFlow.
Единые правила делают тексты одинаковыми по стилю и терминологии, ускоряют работу авторов и упрощают ревью.

## Для кого это руководство

- Технические писатели, которые создают и редактируют документацию.
- Разработчики и аналитики, которые пишут README, описания API и инструкции.
- Ревьюеры, которые проверяют документы в Pull Request.

## Какие документы охватывает

| Вид документа | Читатель | Шаблон |
| --- | --- | --- |
| Руководство пользователя | Пользователь сервиса | [Инструкция](doc-templates/instruction.md) |
| Справочник REST API | Разработчик-интегратор | [Метод API](doc-templates/api-method.md) |
| README и внутренние инструкции | Разработчик команды | [Инструкция](doc-templates/instruction.md) |

## Цели руководства

1. Единообразие: один и тот же объект называется и оформляется одинаково во всех документах.
2. Скорость: автору не нужно придумывать структуру и формулировки с нуля.
3. Проверяемость: часть правил проверяет линтер, остальные проверяет ревьюер по чек-листу.

## Как пользоваться

1. Перед началом работы откройте нужный [шаблон](doc-templates/instruction.md).
2. Пишите текст по правилам разделов «Стиль изложения», «Орфография и пунктуация» и «Оформление текста».
3. Термины сверяйте с [глоссарием](glossary.md).
4. Перед созданием Pull Request запустите линтер, как описано в `CONTRIBUTING.md`.

## Приоритет правил

Если правило конфликтует с удобством читателя, выбирайте удобство читателя и предложите изменить правило через Pull Request.
